Motivation

The Research Question

"How much value does LLM-based sequential decision-making add compared with a strong deterministic API-driven literature review pipeline?"

  • Baseline: Fixed rules, keyword scoring, no LLM — fully reproducible
  • Single-agent: One LLM with tools — plans queries, judges relevance
  • Multi-agent: Delegation and reflection across specialist agents
  • Same topic, same APIs, same output format — apples-to-apples comparison

Embedding Layer

Semantic Scoring via fastembed

Model

  • BAAI/bge-small-en-v1.5 — 384-dim dense embeddings
  • ONNX runtime, no GPU required
  • ~130 MB download (once, cached)
  • Runs via fastembed Python library

MaxSim Scoring

  • Paper → title + abstract sentence segments
  • Survey config → topic + RQs + hints as query vectors
  • MaxSim: max(cosine(seg_i, query_j))
  • Normalised to [0, 1]: (cosine + 1) / 2

Server Flow

  • Load model → embed query segments
  • Batch-embed all paper segments at startup
  • Write embedding_score to NDJSON
  • Live search: embed new query, compare to index
Both scores coexist: score (keyword, pipeline) and embedding_score (semantic, server) — sortable in the UI

  • 1
    DOI

    arXiv ID
    Preprint version identifier
  • 3
    OpenAlex ID
    Cross-source persistent ID
  • 4
    Semantic Scholar ID
    S2 internal paper ID
  • 5
    Title + Year + Author fingerprint
    Normalised: lowercase, stripped punctuation

Merge strategy

  • Merge source lists (track all sources that found the paper)
  • Prefer non-empty abstract
  • Prefer canonical URL (DOI > arXiv > landing page)
  • Merge all identifiers (DOI from one source + arXiv from another)
  • Preserve all raw metadata from all sources

Data Model

Paper Identity & Persistence

paper_id — assigned at write time

def make_paper_id(p: PaperCandidate) → str: key = ( p.identifiers.doi or p.identifiers.arxiv_id or p.identifiers.openalex_id or p.identifiers.semantic_scholar_id or f"{title.lower()}:{year}" ) return "p" + sha256(key).hexdigest()[:15]
Same paper found by any source → same ID. Stable from first write. Used as primary key for CRUD operations.

Persistence format: NDJSON

  • Grep-friendly — one JSON record per line
  • Git-diffable — append-only by pipeline runs
  • Atomic overwrite by CRUD API (.tmp → rename)
  • Site exports as pretty JSON for the frontend
data/papers.ndjson — accepted, append
data/rejects.ndjson — rejected, append
site/data/papers.json — export, overwrite

Limitations

Known Limitations

⚠ Semantic Scholar rate limiting

Free tier: ~1 req/s. Under sustained load (14+ queries), S2 returns HTTP 429. Pipeline continues gracefully — S2 results are simply missing for that query.

Fix: Add an API key via X-API-Key header in semantic_scholar.py for higher rate limits.

⚠ OpenAlex question-form queries

Research questions containing ? triggered HTTP 400 Bad Request from OpenAlex. Fixed by stripping ? before sending.

Now resolved in openalexapi.py.

⚠ NDJSON append accumulation

Pipeline appends to NDJSON on each run. Running multiple times accumulates duplicates in the raw file. The server CRUD API uses atomic overwrite (no accumulation).

Best practice: Clear data/papers.ndjson before re-running the pipeline.
